Why build it?

A first telemetry packet can require setting up a build, creating an application, finding message IDs and interpreting events. The project asks how much of that preparation can be automated while keeping the student in contact with real flight software.

Inside the system

Three components, one connected workflow

The web interface describes an operation. A Python backend translates between that interface and the running cFS process. Commands travel toward the flight software; telemetry returns with the state of its applications. Select a component to explore its responsibility.

WEBHTTP / REST ⇄PYTHONUDP ⇄cFS

Web interface

BROWSER / HTTP

Commands, telemetry, mission planning and an architectural view share one interface. The student can relate a low-level operation to the purpose of the mission.

Python service

PYTHON / API

Python connects the editor, application generation, source analysis and Ground Station. It sends commands and decodes telemetry through the build-derived catalogue. The browser uses JSON over HTTP and polls job and Ground Station state every 1.5 s.

cFS on Linux

cFS / UDP

The actual cFS applications and cFE services run on Linux. Captures cover both the native host and ARM64 Linux inside QEMU. CI_LAB receives commands and TO_LAB returns telemetry over UDP; the project retains the cFS build system.

Inside the system

A look through the cFS layers

Applications use shared flight services. Portability comes from separating those services from the operating system and platform. Open each layer to see what changes and what can be reused.

APPSCI_LAB · TO_LAB · SCH_LAB
cFEES · SB · EVS · TBL · TIME
OSALAPI
PSPLINUX / PLATFORM
HARDWARE / LINUX

Mission applications

Mission-specific logic and reusable apps: command input, telemetry output, scheduling, housekeeping and monitoring. The thesis discusses CI_LAB, TO_LAB, SCH_LAB, HK and HS, among others.

cFE · shared services

Executive Services manages applications; Software Bus routes messages; Event Services reports events; Table Services manages tables; Time Services provides the time reference.

OSAL · operating system

The Operating System Abstraction Layer exposes operating-system functions through a common API. It helps the application code depend less on a particular OS.

PSP · platform

The Platform Support Package contains the platform-specific support cFE needs. This execution used Linux on the host and on an emulated Raspberry Pi. Evaluation on a physical low-cost board remains a separate thesis objective.

From source definitions to a usable interface

Flight Studio brings the development cycle into one workspace: create an application, inspect the relationships extracted from C, build for the selected target and inspect the resulting commands and telemetry.

01

Create & integrate

The generator previews the application files and build integration before writing them. The captured orbit_lab example shows that preview; no new app was created for the screenshots.

02

Discover interfaces

The architecture view extracts function and command relationships from C. Ground Station uses the build compiler to recover identifiers, sizes and field offsets, connecting the editor to the packets actually sent.

Events, decoded fields and raw bytes appear together. A learner can connect SAMPLE_APP_NoopCmd to its event and the counter change, then return to the implementation that caused them.

The repository defines an initial temperature of 23.5 °C, amplitude of 5 °C and period of 30 s. Move along one period to see how seconds become a sensor value.

Python

sample(seconds, initial_c) produces a temperature in degrees Celsius. The simulator multiplies it by 1000 and rounds to the integer millidegrees expected by the QEMU property.

QMP / TMP105

qom-set writes the temperature property of the TMP105 device through the QMP Unix socket. An empty return object becomes OK in the interface. This is the boundary verified by the sensor capture.

I²C / Linux

Inside Linux, the driver accesses the TMP105 at I²C address 0x48 on bus 1. linux_i2c_lib supplies the bus access and tmp105_lib interprets the device registers. Both libraries were loaded by the captured cFS mission.

cFS / Telemetry

A sensor application must read the library, publish a message on Software Bus and include it in the telemetry route. The captured mission had no sensor-reading app: this last path is explained from the repository architecture, and is not presented as an observed end-to-end sensor test.

QMP · OK

Observed in QEMU

The recorded TMP105 sample was 27.830 °C → 27830 m°C, with QMP reporting OK. The magnetometer Y axis likewise received 17.321 µT → 17321 nT. These acknowledgements confirm injection into the device models.

What this work establishes

Flight Studio

The native cFS runtime reached OPERATIONAL. A command sent through Flight Studio produced a NOOP event and an incremented application command counter in telemetry. The thesis defines the next evaluation: quantify development effort, latency and usability with repeatable measurements and users.

Sources & scope

Architecture and evaluation context: supplied TCC 1. Implementation and screenshots: the supplied cfs_emulator repository, executed locally. The technical and educational targets are still evaluation criteria, not benchmark results from this capture session.

Pourquoi le développer ?

Une console, une horloge et plusieurs tâches semblent simples de l’extérieur. Ici, chaque comportement repose sur des écritures mémoire, des sauvegardes de registres et des décisions d’ordonnancement. Le projet rend visible le lien entre C, assembleur et machine.

void ordonnance(void){    unsigned long flags = irq_save();    processus_t *ancien = actif;    uint32_t maintenant = nbr_secondes();     for (int i = 1; i < n_proc; ++i) {        processus_t *p = &table_des_processus[i];        if (p->state == WAIT && (int32_t)(maintenant - p->hour_wake_up) >= 0) {            p->state = RUNNABLE;            printf("Fin du sommeil de %u s du processus %d\n", p->temp_sommeil, p->pid);        }    }     if (ancien->state == RUN) {        ancien->state = RUNNABLE;    }    /* Le tour inclut la tâche actuelle : idle reste disponible si tout dort. */    for (int distance = 1; distance <= n_proc; ++distance) {        processus_t *suivant = &table_des_processus[(ancien->pid + distance) % n_proc];        if (suivant->state == RUNNABLE) {            suivant->state = RUN;            actif = suivant;            if (suivant != ancien) {                ctx_sw(ancien->reg, suivant->reg);            }            break;        }    }    irq_restore(flags);}

Une adresse est une opération

Les mêmes instructions de lecture et d’écriture accèdent aux données ou aux registres d’un périphérique. Sur cette machine CEP, framebuffer, UART et timer occupent des adresses physiques distinctes. Sélectionnez une région pour relier adresse et opération.

Au cœur du système

Un processus a un cycle de vie

La table contient quatre places, dont idle. L’ordonnanceur parcourt les tâches prêtes. Le sommeil enregistre une échéance ; la fin marque la tâche DIE. Sélectionnez un état pour comprendre si une tâche peut s’exécuter.

RUN

RUN · C’est la tâche active. Une interruption du timer peut donner la main à la prochaine tâche prête.

RUNNABLE

RUNNABLE · La tâche possède un contexte et peut être sélectionnée. Une nouvelle tâche commence dans cet état.

WAIT

WAIT · dors() enregistre une échéance de réveil. L’ordonnanceur rend la tâche prête quand elle est atteinte.

DIE

DIE · fin_processus() termine la tâche. Le retour de sa fonction mène aussi à la fin via proc_launcher().

Ce que ce travail établit

Un noyau, octet par octet.

Le projet relie pixels, console, E/S série, interruptions timer et ordonnancement dans un noyau RV64 exécutable. Les démonstrations ont été capturées depuis le dépôt lié dans QEMU CEP, avec des extraits de code pour chaque activité.

Sources et périmètre

Le code et les captures correspondent à l’état actuel du dépôt, dont les exemples intègrent des corrections ultérieures. Le projet original du cours était individuel ; boot/plateforme, runtime et police conservent leurs crédits. Les pixels ont été exportés de la VRAM réelle de l’invité par le débogueur.

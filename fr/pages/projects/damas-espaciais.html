01 /

L’idée

Damas Espaciais était mon projet de fin de cours en algorithmique et programmation à l’UFSM, en 2021. J’ai choisi les dames parce que les règles sont simples et que je les connaissais bien : je pouvais ainsi consacrer mon énergie à apprendre le C et la bibliothèque Allegro 5.

Le point de départ était un jeu de Pong que le professeur Marcelo Serrano Zanetti avait partagé avec la classe. Le plateau est une matrice de 8 par 8, avec des fusées bleues et roses sur un fond violet.

En 2026, j’ai repris le code. J’ai conservé la version de 2021 dans le dépôt et reconstruit le jeu avec les règles dans un fichier séparé, des tests automatisés et une compilation pour Linux et Windows.

Les mêmes règles que game.c

Ce plateau utilise les règles en C du jeu restauré, compilées en WebAssembly. Sélectionnez une fusée puis sa destination. L’inspecteur explique chaque vérification ; le moteur C décide si le plateau change. Jouez à deux sur le même appareil, à la souris, au toucher ou avec les flèches et Entrée.

Les bleus commencent, depuis le haut du plateau.
Cliquez à nouveau sur la fusée sélectionnée pour passer votre tour, comme dans l’original. Dans le jeu de bureau, le bouton gauche sélectionne et le droit déplace.

Le plateau nécessite JavaScript et WebAssembly. Vous pouvez aussi ouvrir la version autonome pour navigateur ou télécharger le code source. Ouvrir le jeu dans le navigateur

Inspecteur de coups · game_can_move() Sélectionnez une fusée pour commencer.
  1. ·Les deux cases sont sur le plateaugame_inside(row, col)
  2. ·La fusée appartient au joueur du tourgame_owner(piece) == game->turn
  3. ·Cliquer sur un adversaire adjacent désigne la case au-delàlanding(game, row, col, &to_row, &to_col)
  4. ·La destination est vide et sur le plateauboard[to_row][to_col] == EMPTY
  5. ·Le déplacement est diagonal, d’une ou deux casesabs(dr) == abs(dc) && abs(dr) <= 2
  6. ·Les fusées ordinaires avancent uniquement!(piece == BLUE && dr < 0)
  7. ·Un saut de deux cases passe sur un adversairegame_owner(middle) == 3 - game->turn

Tout était dans un seul fichier. Les règles, le dessin, la souris et les sons partageaient des variables globales, et chaque couleur avait sa copie des fonctions de déplacement.

  • AvantLe code tentait de capturer deux pièces en un saut, sans traiter tous les cas de la même manière.
  • AvantLes dames n’étaient pas comptées parmi les pièces restantes.
  • AvantCertains coups lisaient des cases hors du plateau avant de vérifier les coordonnées.

Les mêmes règles C compilées en WebAssembly, avec commandes à la souris, au clavier et au toucher

Les règles ont rejoint un fichier séparé, sans code Allegro. La fenêtre, les écrans, les entrées et l’audio sont restés dans main.c ; les tests accèdent directement aux règles.

  • CorrigéLes coordonnées sont vérifiées avant de lire le plateau, y compris la case d’arrivée d’une capture.
  • CorrigéUn coup est entièrement validé avant toute modification. Un coup invalide préserve le plateau et le tour.
  • CorrigéLes dames comptent comme pièces, conservent leur type lors des captures, et la promotion fonctionne en déplacement comme en capture.
  • ChoixUne capture par tour, car l’ancienne double capture était incohérente. Un joueur sans coup possible perd désormais.

06 · Ce que j’ai appris

En 2021, j’ai d’abord écrit le jeu en C pur, puis ajouté Allegro : j’ai dû adapter beaucoup de lignes de code. En reprenant le projet en 2026, j’ai séparé les règles du code Allegro. C’est ce qui m’a permis de tester chaque coup sans ouvrir de fenêtre.
